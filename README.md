# Конструктор документов (Typst + WASM)

Полностью статический сайт: выбираете шаблон документа, заполняете поля
(или оставляете пустыми — в PDF появляются прочерки для ручного заполнения)
и скачиваете готовый PDF. Компиляция Typst в PDF происходит **прямо в браузере**
через WebAssembly, без бэкенда.

## Как это работает

- **Шаблон** — файл `templates/*.typ`, определяющий функцию `doc(..)`.
  Для сгруппированных схем (см. ниже) это `doc(data)`, где `data` — словарь,
  сгруппированный по разделам схемы. Пустое значение рендерится как линия.
- **Схема полей** — рядом лежит `templates/*.schema.json`. Поддерживаются два
  формата:
  - *Группированный* (рекомендуется): `{ id, name, groups: [ { id, title,
    repeatable?, fields: [ { key, label, type, required?, placeholder?,
    options?, autocomplete? } ] } ] }`. Раздел = шаг заполнения; `repeatable`
    разрешает несколько сторон (покупателей/продавцов). Приложение вызывает
    `doc(data: ( <group_id>: <словарь|массив словарей>, ... ))`.
  - *Плоский* (обратная совместимость): `{ id, name, fields: [...] }` — один
    шаг, вызов `doc(ключ: "значение", ...)`.
- Поле `type` управляет мобильной клавиатурой и контролом: `text | tel | email
  | date | number | textarea | select`.
- Приложение подставляет значения в вызов `doc(..)` и отдаёт итоговый исходник
  в `@myriaddreamin/typst.ts` (WASM), который возвращает PDF.
- Введённые стороны (`repeatable`-разделы) можно сохранить и повторно
  использовать в любом договоре с тем же `group.id` — они хранятся в
  `localStorage` браузера.

## Разработка

```bash
npm install
npm run dev      # локальный предпросмотр
npm run build    # сборка в dist/ (статический сайт)
```

## Добавление шаблона

1. Создайте `templates/my-doc.typ` с функцией `doc(..)`.
2. Создайте `templates/my-doc.schema.json` с описанием полей.
3. Добавьте запись в `src/templates.js`.

## Публикация

GitHub Actions (`deploy.yml`) собирает `dist/` и выкладывает на GitHub Pages
при пуше в `main`. Включите Pages в настройках репозитория (Source: GitHub Actions).
Цветовая схема интерфейса — Gruvbox (тёмная).
